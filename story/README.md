# 台本管理

台本ブラッシュアップ時は、最初に [`現行統合台本.md`](./現行統合台本.md) を確認してください。現在の画面に出る本編、スタッフロール、APEIRONCENEを安定ID付きで一冊にまとめています。

## ファイルの役割

- `現行統合台本.md`: 現行表示の統合レビュー版。`npm run story:export`で実行データから生成します。
- `USER_SCRIPT_2026-08-24.txt`: ユーザー提供の全編改稿を原文のまま保持する入力です。
- `APPROVED_SCRIPT_2026-08-24.md`: 全編改稿と2026年9月6日のLOG修正を安定ID・操作・演出メタデータへ変換した、本編380ステップ（スタッフロール接続を含む）とAPEIRONCENE 3シーン／164メッセージの現行入力です。
- `LOG_COMMENTS_2026-09-06.md`: ユーザーが提供した109件のLOG修正コメントを保持しています。
- `LOG_REVISION_2026-09-06.json`: 修正元のLOG ID、原稿ID、反映先IDと重複整理の対応表です。APEIRONCENEの画面IDは`runtimeStepId`で保持し、追加・削除で後続IDを振り直しません。
- `LOG_COMMENTS_2026-09-06_BEYOND.md`: 同日11:56 UTC出力のAPEIRONCENE追加改稿59件です。先行する109件の原文・対応表は履歴として保持します。
- `LOG_REVISION_2026-09-06_BEYOND.json`: 追加改稿59件と18メッセージの挿入対応表です。未修正本文・本編のハッシュと既存LOG ID順を検証し、先行改稿の上書き対象を明示します。
- `LOG_REVISION_2026-09-06_BEYOND_FOLLOWUP.json`: 統合台本確認後の追修正2件（`beyond_03_043`の話者をルウへ、`beyond_01_028`の非人型描写とページ分割）の記録です。`npm run check:story-log-comments`で、旧ログの保持と対象外542項目・シーン順・安定IDの不変を検証します。

- `../novel-story-data.js`: 凍結入力と差し替えを土台に、承認済み入力のID順と本文を適用して生成される本編ランタイム。直接編集しません。
- `../true-end-data.js`: 承認済み入力から生成されるAPEIRONCENE 3シーンのランタイム台本。直接編集しません。
- `../novel-mode.js`: 本編最終行からスタッフロール、さらにAPEIRONCENEへ接続する処理とクレジット本文。
- `../contest-limited/story/limited-feature-script.md`: `物語台本.md`と同一の保持コピー。統合レビュー版ではありません。

## ブラッシュアップ手順

1. `現行統合台本.md`で対象IDを確認する。
2. 修正内容をID単位で決める。
3. 現行本文の修正は`USER_SCRIPT_2026-08-24.txt`へ反映し、`scripts/import-plain-story.mjs`で`APPROVED_SCRIPT_2026-08-24.md`を再生成する。凍結入力と旧差し替えJSは互換メタデータの土台として維持する。
4. `npm run data:novel`で本編とAPEIRONCENEのランタイムを生成し、`npm run story:export`を実行する。
5. `npm run check`で統合台本とランタイムが一致することを確認する。

番号付き入力の`* ID:`は全項目へ指定します。本文や話者を変更してもIDを維持し、追加する本文には未使用IDを割り当てます。`* 演出メタ:`は背景・時系列・操作の引継ぎ、`* 時刻:`はチャットの表示時刻です。`welcome_chat_095`は本文を隠さないようスタッフロール専用の転換ステップとし、終幕の地の文はその直前へ置きます。

統合台本へ直接書いた案は、自動的には製品表示へ入りません。実装ソースへ反映せず統合台本だけが変わった場合、`npm run check`が不一致として停止します。これにより「読んでいる台本と現在のシナリオが違う」状態を検出します。
