## 依頼・対象・状態

ユーザー原文：「ストーリーモード入ってエンディングまで行ってないのにこれになったんだけど　違うでしょ」。添付画像は、入口の主ボタンが `TRUE END / UNLOCKED 星々の放課後 ～APEIRONCENE～` になっている画面。

対応方針：未クリアのプレイ状態では本編入口を表示し、クリックしても後日談へ入らない。本編エンディングからの正規解放は維持する。保存データ全消去をユーザーに求めない。

- 対象：`eef5ac9e519913127dd5e6df0095a25dcfdb19bb` ＋本修正のローカル作業ツリー。ランタイム5ファイルのSHA-256は後述の各 `report.json` に記録。

- 旧 `eef5ac9` の展開検証済みリリース成果物には本修正が入っていない。公開再開時は本修正を含むコミットから成果物を作成し、その対象版で再検証する。

## 再現と原因

ユーザーの実ブラウザーの保存領域は読み取っていない。独立したテスト用ブラウザーで、現行版の未クリア進捗 `clear: false` と古い `gaiaSensewareTrueEnd:pending:v1` が併存する条件を作った。

修正前にPC1440×900・スマホ390×844で、音声OFF → タイトルのストーリー入口 → 白いプロローグの「本編へ」 → 本編最初の場面 → 「戻る」を実クリック／タップ。同じ入口が添付画像の解放表示になった。メモリーと保存済み進捗は両方とも `clear: false` だった。

確認した原因・関連経路：

1. 入口の判定が、現在の本編クリア状態と無関係に古い `pending` だけで後日談を解放していた。
2. 新規開始や途中セーブのLOADでも、以前の `pending` が残っていた。
3. 章ジャンプのエンディング・後日談プレビューでも、一部のクリア状態／完了マーカーが書き込まれていた。
4. 物語を遅延読み込みする前は、旧版セーブを物語側と同じ移行条件で判定していなかった。

証跡：`artifacts/story-unlock-state-2026-09-10/before/`。実際のユーザー保存内容の確定診断ではなく、報告と同じ表示・操作を再現した原因である。

## 変更

- `app.js`：本編クリアを必須条件とし、`pending` 単独では解放しない。読み込み済みなら物語側の正規化済み完了状態を参照。未読み込みなら現行セーブの真偽値を確認。主ボタンを押す時にも行き先を再判定。
- `novel-mode.js`：`getCompletionState()` を追加し、通常プレイと保存済み進捗を章プレビューから分離。未クリア進捗の保存時に古い `pending` だけを除去。章プレビューではクリア状態を永続化しない。後日談への直接イベントにも未クリアガードを追加し、正規起動ではセッション・到達地点を維持。
- `true-end-mode.js`：プレビュー起動では後日談完了・到達・公開用完了イベントを永続化しない。
- `gaia-mode-loader.js` / `index.html`：変更ランタイムとローダーのキャッシュ識別子を更新。
- 回帰スクリプト2本と `package.json` の `check:story-unlock` / `check:story-unlock:browser` を追加。

手動セーブ、既存ギャラリー、過去の後日談完了記録を消去しない。台本・素材・デモ内容・公開先設定は変更していない。

`node scripts/check-story-unlock-lifecycle-browser.mjs`

8種類の入口条件を、物語の遅延読み込み前後で照合：保存なし＋pending、未クリア＋pending、旧版クリア＋pending、文字列false、壊れたJSON、現行クリアのみ、本編／後日談両方完了、過去の後日談完了後に新しく本編を完了した場合。

PC・スマホ幅それぞれで以下の3系統を実操作：

1. 本編序盤をSAVE → 最終ナレーション直前の未クリア自動セーブを開始条件にして実際にページを進める → クレジット → 観測入口へ戻る → 後日談解放 → 主ボタンから後日談 → 各章の正規スキップ操作でフィナーレ → 戻る。正規のクリア／到達／完了マーカー、完了イベント1回、元のセッションと到達地点、手動セーブ保持を確認。
2. 本編へ再入場 → 古いpending付きの状態で序盤のSAVEをLOAD → 未クリア・本編入口へ戻る。手動セーブ・ギャラリー・過去の後日談完了記録を保持。LOGの全台本Markdownを実ダウンロードし、内容を確認。
3. 未クリアの独立したブラウザーで開発用章ジャンプを明示的に有効化し、エンディングと後日談を最後までプレビュー。どちらも進捗をクリア扱いにせず、pending／reached／completeを保存しない。完了イベント0回、入口は本編のまま。通常のrelease設定では後日談の章ジャンプ項目がないことも確認。

全章を最初から読んだ通し試験とは区別する。正規クリア試験は最後のナレーションを開始位置にしており、`clear: true` の直接注入や章ジャンプで正規クリアを代替していない。
