## 再現と修正

変更前の実ブラウザで 06 → 統計分析を開き、説明末尾の内部スクロールを再現した。`before/report.json` とスクリーンショットを保存。

| ビューポート | グラフ上端・変更前 | グラフ上端・最終版 | 説明内部の超過・変更前 → 最終版 |
| --- | ---: | ---: | ---: |
| 1440x900 | 377.73 px | 316.75 px | 50 → 0 px |
| 3442x1690 | 803.92 px | 529.92 px | 34 → 0 px |

スクロールバーだけを隠して修正扱いにはしていない。PC の報告画面は注意書きまで収まり、全画面と説明欄の縦方向超過がともに 0。スマホ・横向きでは読める文字サイズを保ち、外側の一続きのスクロールで全文へ到達できる。長い観測一覧・分析解説や拡大表示に必要なスクロールは残している。

発光には二つの原因があった。

1. ホバー時の `translateY(-2px)` でボタンの位置が変わり、共通発光レイヤーの位置検査がアニメーションを停止していた。ラボ内のヒット領域を静止させた。
2. 遅延追加されたラボと共通発光レイヤーが同じ z-index で、発光がラボの裏に描画されていた。ラボを発光の一段下へ調整した。単に CSS が active であることだけでは、この不具合を検出できなかった。

実際の表示画像で左 → 中央 → 右へ光が走ることを確認。70/120/180ms に固定した CSS フレームを、同じホバー状態で発光だけを一時非表示にした対照画像と画素比較した。

| 固定フレーム | 見た目が変化した画素数 / 対象画素数 |
| --- | ---: |
| 70 ms | 930 / 8820 |
| 120 ms | 1217 / 8820 |
| 180 ms | 1133 / 8820 |

上記は可視化のための固定フレーム。これとは別に通常時間経過で、ホバーとキーボード Tab フォーカスの発光、枠位置、180ms 時点の表示、終了後に残らないことも検証した。`prefers-reduced-motion` では走る光を出さず、静的なフォーカス表示を保つ。

関連画面の目視で、観測データの行名が白地に非常に薄い色になっていることも確認し、読み取り用の濃色へ修正。計算値・出典情報は維持した。
