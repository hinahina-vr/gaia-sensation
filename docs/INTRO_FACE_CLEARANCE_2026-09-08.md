# 入口画面で顔に重なる文字の修正

## 対象と再現

2026-09-08の添付画像にある、スマホのデータ入口画面でみずの顔に「SENSEWARE」等が重なる症状を修正。基点は本番と同じ `fc510bf5a84517788e8227e3757634cab5f9e171`。今回の依頼はローカル修正であり、コミット・プッシュ・デプロイは行わない。

同コミットのCSSをローカルChromeへ配信し、タイトル→サウンドOFF→スキップ→データ入口→入口ガイドを閉じる、という実操作で確認した。390×864の通常状態・TRUE END解放状態とも、顔領域に見出し・タグライン・説明文の4テキスト矩形が重なった。320×568でも4件を再現。解放状態は試験専用ブラウザーの進行データfixtureであり、物語を実クリアした試験ではない。

## 変更

- `styles.css`: 幅720px以下またはタッチ向けの入口で、既存背景の上部に人物を見せる領域を確保。画像を右側に寄せて二人の顔を見せ、背景の下端を暗い地色へなじませる。見出しは画像領域の中間点より28px以上下に置き、短い画面では必要な分だけ縦スクロールさせる。データ入口以外のステージへ背景サイズの指定を広げない。
- `gaia-mode-loader.js`・`index.html`: 更新後CSSとローダーのキャッシュキーを追加。既存の再資源化版キーは維持してsuffixを追加した。
- `scripts/check-intro-face-clearance-browser.mjs`: 変更前CSSの再現、実画像のobject-fit・位置・変形を反映した顔領域と表示文字の重なり検出、実操作の回帰試験を追加。

背景画像そのもの、コピー、データ、保存仕様、センサー・AI処理は変更しない。通常のマウス操作PCの背景サイズ・位置と見出しレイアウトは維持する。

## 検証結果

- ローカルChrome計9ケースが合格: 390×864通常／解放後、320×568、430×932、390×844動作軽減、768×1024タッチ、844×390タッチ横向き、1440×900 PC、1920×1080 PC。
- 全ケースで顔と入口の文字の重なり0。顔を画面外へ隠して解消していないこと、入口本体が画面幅に収まること、文書全体の横溢れ0を確認。390×864では顔領域の下端約234pxに対し、見出し上端約270px。
- 390×864→844×390→390×864の同一画面内のサイズ変更でも重なり0。
- 全ケースで4つの入口の44px以上の操作領域とスクロールでの到達、入口ガイドの再表示・閉じる、地図へ入る→紹介を閉じる→地図から戻る→タイトルへ戻るを実操作して合格。ページ例外・CSP違反0。
- 添付と同じ解放後のスマホ画面、320px、横向き、タブレット、PCのPNGを開いて目視確認した。
- `npm run check`: precheck・postcheckを含む全体が合格。初回の旧キャッシュキー照合失敗は、既存キーへのsuffix追加に直して再実行した。`node --check scripts/check-intro-face-clearance-browser.mjs` と `git diff --check` も合格。

再現コマンド:

```text
node scripts/check-intro-face-clearance-browser.mjs --before --baseline=fc510bf5a84517788e8227e3757634cab5f9e171 --profiles=mobile390,mobile390-unlocked,small320,pc1440
node scripts/check-intro-face-clearance-browser.mjs
```

既定の対象URLは `http://127.0.0.1:4447`。URLを引数で指定可能。最終証跡は `artifacts/intro-face-clearance/after-final-mobile/report.json`（2ケースと回転）と `after-responsive/report.json`（7ケース）。変更前の落ち着いた表示は `before-settled/report.json`。各最終レポートの実装3ファイルのSHA-256を現物と照合している。

## 確認範囲の限界

ローカル実Chromeとスマホ／タッチのエミュレーションであり、物理端末・Safari/Firefox・本番配信は未確認。ライブAPIは試験用エラー応答に隔離しており、実提供元の状態を確認したものではない。保存・書き出し・実センサー送信・AI送信・物語保存／読込は変更対象外で今回再実行していない。ZIP等の配布物は作成していない。

320pxでは `intro-layer` 内部の20pxの横幅超過が変更前後とも記録される。既存状態として未修正で、今回の入口本体の幅と顔の保護、文書全体の横幅とは分けて記録する。全体CIの旧UI依存および既知の動作軽減切り替えアニメーション試験を修正した、という主張もしない。
