## 1. 実装の目的

現在の `novel-mode.js` に入っている旧ストーリーを、最新の『GAIA SENSATION』へ置き換える。

完成時には、プレイヤーが次の流れを20〜30分で体験できること。

1. 学園祭の展示端末で、記録方針を読んでSTARTを押す。
2. サクヤが来なかった三か月前の空席を見る。
3. 一年前へ戻り、文字だけで知り合った三人が初めて会うまでを読む。
4. 三人の制作、失敗、生活音、公開同意を見る。
5. サクヤが来なくなり、二人が安否確認を依頼した経緯を知る。
6. GX、地図、抽象、宇宙の表示を経由しながら、MODE 03、07、08、10を順番に操作する。
7. 本人の記録だけを表示するか、生成した制作過程も別表示で開示するか選ぶ。
8. 自分の文章を自分の名義で表示するか、何も書かずに終えるか選ぶ。
9. 本文ではなく、WRITEまたはLEAVE EMPTYの痕跡だけが次の来場者へ残る。

物語の目的は、サクヤの不在理由を当てることでも、生成文から正解を選ぶことでもない。
「記録されていること」と「人がそこから作ったもの」を分けたうえで、何を表示するかをプレイヤーが決めることにある。

## 5. ファイル構成

台本データを `novel-mode.js` へ再び直書きしない。

推奨構成は次のとおり。

| ファイル | 役割 |
|---|---|
| `novel-story-data.js` | 章、台詞、記録カード、選択、遷移のデータ |
| `novel-mode.js` | 再生、状態遷移、保存、入力、描画 |
| `index.html` | ノベル用DOM、通知、カード、入力欄、運営用消去UI |
| `novel-mode.css` | 本文、人物、記録分類、操作画面、モバイル表示 |
| `scripts/check-novel-story.mjs` | ID、遷移、分類、必須場面の静的検査 |

`index.html` では `novel-story-data.js` を `novel-mode.js` より先に読み込む。変更後はキャッシュ用クエリも更新する。

台本データは、少なくとも次の情報を持てる形にする。

```js
{
  id: "mode07_generated_text",
  type: "record",
  scene: "mode07",
  speaker: "mizuha",
  recordType: "DERIVED",
  text: "「聞こえたつもりになってない？」って、三人で確かめたい。",
  summary: {
    generatedFrom: "公開対象として選定済みの制作チャンネル投稿",
    generatedBy: "MIZUHA",
    selectedBy: "MIZUHA",
    confirmedBySakuya: false
  },
  detailsId: "mode07_generation_details"
}
```

配列上の番号だけでセーブ位置を管理しない。全ステップへ重複しない `id` を付け、保存は `stepId` を基準にする。台詞の追加で全セーブ位置がずれる事故を防ぐためである。

## 6. 必要な表示形式

最新稿は、すべてを通常の台詞ウィンドウだけで表示すると読みにくくなる。最低限、次の表示形式を用意する。

| type | 用途 |
|---|---|
| `chapter` | CURRENT、OPENING、PROLOGUE、各MODE、EPILOGUEの区切り |
| `narration` | 地の文 |
| `dialogue` | ミズハ、アマネ、サクヤの通常会話 |
| `chat` | Slack上の時刻付き投稿 |
| `record` | SOURCE、DERIVED、VISITOR TRACE、VISITOR POSTなどの記録カード |
| `notice` | START前通知、保存方針、公開版を変えない説明 |
| `interaction` | レイヤー切り替え、重ね合わせ、記録の確認 |
| `choice` | 三つの選択 |
| `visitorInput` | 120文字の入力と送信、削除 |
| `result` | 四通りの最終表示、黄色い痕跡、累積件数 |
| `end` | 通常の終幕とSTARTへの復帰 |

通常の台詞と、過去の投稿記録を同じ見た目にしない。

- 通常会話：人物名を名前欄へ出す。
- Slack記録：時刻、表示名、本文を一枚の記録カードにする。
- データ記録：日本語の分類名を先、英語を後に出す。
- 生成履歴：要点を通常表示し、モデル名などは折りたたむ。
- ナレーション：話者名を空欄にし、人物色を付けない。

一つの段落を一クリックへ細かく分けすぎない。地の文は一画面に1〜3文を基準とし、物、行動、場面転換の単位で送る。

## 7. 話者の見分け方

誰の台詞か、色を見なくても名前で分かるようにする。色は補助として使う。

| 話者 | 表示名 | 見分け方 |
|---|---|---|
| ミズハ | ミズハ | 名前欄、ミズハ用アクセント、対応する立ち絵 |
| アマネ | アマネ | 名前欄、アマネ用アクセント、対応する立ち絵 |
| サクヤ | サクヤ | 名前欄または時刻付き投稿カード、サクヤ専用アクセント |
| プレイヤー | あなた / VISITOR | 黄色の操作・投稿領域 |
| 地の文 | 表示なし | 白〜灰色、立ち絵の強調なし |
| システム | GAIA SENSEWARE | 記録カードまたは通知パネル |

文字色だけで話者を区別しない。名前、配置、カード形状のうち二つ以上を併用する。

サクヤ用の正式な立ち絵素材は、現在のアセット一覧では確認できない。別人物の絵や抽象SVGを代用品として人物絵にしない。素材制作が別途決まるまでは、初対面を含め、台本の地の文、名前表示、投稿カード、三つ目の席や持ち物で存在を示す。

## 8. 記録分類のUI

分類は必ず日本語を先に表示し、英語だけにしない。

| 分類 | 色 | 必須ラベル |
|---|---|---|
| 観測記録 | 白 | `観測記録 / SOURCE` |
| その場の観測 | 緑 | `その場の観測 / LOCAL SOURCE` |
| 計算・解釈 | 青 | `計算・解釈 / DERIVED` |
| 仮定 | 紫 | `仮定 / SCENARIO` |
| 操作記録 | 薄い黄 | `操作記録 / VISITOR TRACE` |
| 来場者の投稿 | 黄 | `来場者の投稿 / VISITOR POST` |

MODE 07の二枚は、色だけでなくカード自体を分ける。

1. サクヤが送信した白いSOURCEカード
2. ミズハが生成し選定した青いDERIVEDカード

青いカードの通常表示に、次をすべて出す。

- 生成文の全文
- `計算・解釈 / DERIVED`
- 公開対象として選定済みの制作チャンネル投稿からローカル生成したこと
- 生成実行：MIZUHA
- 選定責任：MIZUHA
- サクヤ本人の確認：なし

次だけを「生成履歴を詳しく見る」へ入れる。

- 参照した範囲と対象外の範囲
- 複数候補から一件を選んだこと
- ツールとモデル名
- 生成時刻
- 人による本文編集の有無

重要な判断材料を折りたたみの中へ隠さない。

## 10. 各操作画面の要件

### 最初の小さな選択

選択肢は次の二つ。

- 売り場の温度計から見る / LOCAL FIRST
- 最寄り観測所の記録から見る / STATION FIRST

選んだ項目だけを見て終わらせない。選択後にもう一方も開き、二つの値を別の記録として表示する。

保存するのは開いた順だけ。MODE 10で生活音を再生する順と、最終操作記録へ反映する。

### GXモード｜太古の海

- 既存のGX描画エンジンを、ストーリー用の短い操作へ使う。
- 46億年の全展示を自由閲覧させず、太古の海、光合成、酸素化に必要な区間だけを通す。
- プレイヤーが水面を複数回なぞると、青緑の点と海の色が変わる。
- SOURCEと、鑑賞用に並べたDERIVEDの時間軸を区別する。
- 「酸素は後世の生物のために作られた」という目的の説明にしない。
- 操作完了後、ノベルへ戻ってMODE 03の地図を開く。
- GXを通過済みとしてセーブする。
- 動きを減らす設定では、ボタン操作と短い段階表示で同じ順序を確認できる。

GXは時間を広げる表示である。ここで地図、地震、生成文、最後の選択まで扱わない。

### MODE 03｜地図モード／森の気候装置

- GXの太古の海から、現在の森林分布がある地図へ連続して切り替える。
- 森林と降水量を別レイヤーで出す。
- プレイヤーが両方を表示し、重ねた状態まで確認したら進める。
- 同じ場所にあることは示すが、この画面だけで因果を断定しない。
- サクヤが短くしすぎた文と、三人で直した文を履歴として並べる。
- 02:13の作業連絡と02:14の最後の受信文を、別投稿のまま続けて見せる。

MODE番号と内部配列番号を混同しない。既存の0始まりのモード連携を使うなら、MODE 03は `index: 2` である。

### MODE 07｜抽象モード／届いた時刻、開いた時刻

- 最初に震源と観測点を地図で示し、地名と境界線を外して抽象表示へ切り替える。
- プレイヤーが観測点へ触れると、地震の起点からP波とS波が広がる。
- 到着差を距離、波、色、時刻で示す。
- 起きた時刻、届いた時刻、開いた時刻が別であることを視覚化する。
- サクヤの受信時刻は02:14、二人が開いた時刻は10:27。
- 4.8秒、未送信本文、入力中時間の保存は使わない。
- 白いSOURCEと青いDERIVEDを別カードで見せる。
- 二人の衝突は台本どおり最後まで表示する。
- プレイヤーは両方の情報欄を確認する。
- ここでは選択肢を出さない。
- 詳細な生成履歴は任意閲覧で、開かなくても先へ進める。

MODE 07は既存連携では `index: 6`。

### INTERLUDE｜十二分の海

通常のノベル画面として実装する。
選択、データ説明、SOURCE詳細パネルを差し込まない。
缶コーヒー、水、青りんご、十二分のタイマーを優先する。

### MODE 08｜地図モード／三つの生態系

- 自然環境
- 人の暮らし
- 土地の記憶

抽象表示から海岸線と地名のある地図へ戻す。
三つをカードまたはレイヤーで切り替える。横スクロール表にしない。

三つを見たあと、来場者欄の更新履歴を表示する。

- 画面実装：AMANE
- 問いかけ：MIZUHA
- 回答必須の解除：SAKUYA
- 本編への接続：MIZUHA / AMANE

この場面ではまだ入力させない。サクヤが未来を予見してエンディングを用意したように演出しない。

MODE 08は既存連携では `index: 7`。

### MODE 10｜宇宙モード／最後の受信文

地図から地球全体まで視点を引く。
プレイヤーが地球を回すと、GX、MODE 03、07、08で触れた記録が点灯する。
その後、MODE 03、07、08の記録を一画面へ集める。
ほかのMODEは出典名だけを端へ置き、プレイヤーが体験済みの記録には数えない。

最初の選択に応じて、次の順で音を出す。

- LOCAL FIRST：湯、扇風機、踏切
- STATION FIRST：扇風機、湯、踏切

年越しのハドルで三人が黙っていた十一秒を使う。音声の欠損や4.8秒へ戻さない。

サクヤのSOURCEを表示し、その下へ青い生成カードを閉じた状態で置く。青いカードの存在自体は隠さない。

MODE 10は既存連携では `index: 9`。

### 編集方針の選択

選択肢は次の二つだけ。

- 本人記録で構成する / SOURCE RECORD
- 生成した制作過程も開示する / DISCLOSE DERIVATION

SOURCE RECORDでも、生成した事実を削除したことにはしない。最終表示で本人の記録と並べないだけで、制作記録には残す。

DISCLOSE DERIVATIONでは、白い原文と青い生成文を別作者・別分類のカードとして並べる。

どちらも現在のセッション内表示だけを変える。公開版、次の来場者の初期画面、他端末を変更しない。

### EPILOGUE｜書き込み欄 / WRITE ACCESS

次の順番を変えない。

1. 来場者欄が三人の試作だった履歴を表示する。
2. 二人が不在後に本編へ接続した履歴を表示する。
3. サクヤの続きを書く欄ではないと説明する。
4. 作者名 `VISITOR` と分類 `VISITOR POST` を表示する。
5. 問いを表示する。
6. 保存方針を表示する。

## 12. 保存とプライバシー

### START前に必ず出す通知

STARTボタンより前に次を表示する。

- 進行と選んだ項目は、この端末へ会期中の件数として記録する。
- 入力した文章は次の人へ表示せず、サーバーへ送らない。

「記録について詳しく見る」から、保存先、消去方法、黄色い痕跡の意味を確認できるようにする。

### 投稿本文

- 120文字まで。
- 現在のセッション中だけメモリへ保持する。
- `localStorage`、手動セーブ、オートセーブ、バックログへ入れない。
- `fetch`、Beacon、フォーム送信、ログ送信を行わない。
- 次の来場者へ本文を見せない。
- STARTへ戻るか「この文章を消す」で破棄する。
- HTMLとして解釈せず、必ず `textContent` 相当で表示する。
- 本名、住所、連絡先を書かない案内を入力欄の上に出す。

入力欄の下には常に次の四点を表示する。

`120文字まで／このセッションだけ／サーバー送信なし／次の人に本文は見えない`

### 次の来場者へ残すもの

端末の `localStorage` へ保存してよいのは、本文を持たない次の情報だけ。

```js
{
  eventSessions: 0,
  eventPosts: 0,
  eventLeaveEmpty: 0,
  lastVisitorAction: "WRITE" | "LEAVE_EMPTY" | null,
  markers: ["WRITE", "LEAVE_EMPTY"]
}
```

- WRITEは黄色い点。
- LEAVE EMPTYは黄色い細い円。
- 新しい順に24個まで表示する。
- 25件目以前は `+n` にまとめる。
- IPアドレス、端末識別子、本文、氏名を含めない。

STARTを連打してセッション数が増えないようにする。
「最初からやり直す」と「次の来場者が新しくSTARTする」を内部状態で分ける。
ページ再読み込み後に同じ途中セーブを再開した場合も、新しいセッションとして二重計上しない。

### 運営用の消去

CONFIGの奥など、誤操作しにくい場所へ「イベント記録消去」を置く。
二段階確認後に、累積件数と黄色い痕跡だけを消す。
物語のセーブデータと表示速度設定まで一緒に消さない。

### 旧セーブ

現在の `gaiaSensewareNovel:v5` は配列位置を保存しており、最新稿と互換性がない。

- 新版は新しいキーへ上げる。
- `stepId` を保存する。
- v5の `stepIndex` を無理に新版へ移さない。
- 旧セーブがある場合は「旧版の記録のため再開できません」と知らせ、新しく始められるようにする。
- 表示速度設定は内容と独立しているため、互換なら引き継いでよい。

## 13. 音

物語で中心にする音は次の四系統だけ。

1. アマネの扇風機
2. ミズハが湯を沸かす音
3. サクヤの窓から聞こえる踏切
4. 現在の展示ホール

感情場面でBGMを急に大きくしない。生活音を台詞より前へ出しすぎない。

既存の `assets/audio/` にある楽曲は、実際に試聴してからBGMへ割り当てる。ファイル名だけで生活音の代わりにしない。
扇風機、湯、踏切、展示ホールの専用素材は、現時点の一覧では確認できない。ライセンスを確認した素材が入るまでは、音IDを未設定にできる音声マニフェストを作り、字幕と画面だけでも最後まで進めるようにする。

必要な操作は次のとおり。

- 全体音量
- 音なし
- 音が再生できなかった場合の続行
- 年越しの十一秒をスキップできる操作
- 音の内容を示す字幕

ブラウザの自動再生制限に従い、STARTより前には再生しない。

## 23. 実装担当への最後の注意
