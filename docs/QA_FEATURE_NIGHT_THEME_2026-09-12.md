# MAP・観測案内の配色統一とフォーカスの光

依頼原文: 「2枚目で色味統一　ボタンフォーカスでキラッと　あと不透明度は80%に」

添付1枚目は明るい観測案内、2枚目は濃紺・青緑・紫のMAP案内。主担当の解釈は、両案内のUIを2枚目の配色に統一し、不透明度80%はパネル背景に適用すること。文字・イラストまで薄くしない旨を作業開始時に説明した。

ローカル変更のみ。基点 `db63742c12f0ec9a7538ba7073d6029d384e5e7f`。push・デプロイなし。

## 変更

- `mode-feature-intro.css`: MAP専用だった夜色のパレットを観測案内と共有。見出し、本文、3枚のカード、注意書き、フッター、ボタンの色を統一。イラストの余白にもカードの色を使用。
- パネルの背景グラデーションを独立した描画層に置き、合成後の背景不透明度を `0.8` に設定。文字・画像・操作部分の親のopacityは `1`。外側の暗幕やカードの背景まで一律0.8にする変更ではない。
- 「閉じる」「操作ガイド」「進む」のホバー／キーボードフォーカスで、斜めの光が650msで一度だけ通過。従来の主ボタンの周期的な光は終了。キーボード操作時の輪郭を明示し、動きを減らす設定では光の移動を停止。
- MAPの2:1、観測の3:2のイラスト、本文、カードの配置、開始・再表示・ガイドの手順は変更しない。
- `gaia-mode-loader.js`、`index.html`、`sensors/index.html` の対象キャッシュキーを更新。
- `scripts/check-feature-theme-browser.mjs` を追加し、`package.json` にブラウザ回帰試験と構文検査を登録。既存の `scripts/check-sensor-feature-browser.mjs` は証跡の出力先を環境変数で指定できるようにしただけで、検証内容は維持。

## 検証

- 変更前: 同じ1440×900のChromeでMAP・観測の色の相違を記録。画像読み込み、操作ガイド、再表示、進む、閉じるを確認。
- 最終ブラウザ試験: MAP・観測 × 1440×900 / 3840×2160 / 390×844 / 320×568 / 844×390 / 1440×900の動きを減らす設定、計12ケース合格。共有パレットの完全一致、背景opacity `0.8`、画像opacity `1`、画像の実読み込み、横はみ出しなし、44px以上の操作領域、操作ガイド・再表示・進む・閉じるを確認。通常／動きを減らす設定の両モードで、Tabの3ボタン巡回、可視フォーカス、光の1回再生と終了後の非表示、ホバー、CSP違反なしも確認。
- 観測の既存回帰: 1440×900、390×844の各3入口（公開地図・ログイン・機器管理）、計6ケース合格。地図7段階、他3段階のガイドを完走し、戻る・再表示・Escape・フォーカス復帰も確認。
- 同回帰で、地図の拡大縮小・リセット・検索・該当なし・観測点選択・最新値・ローカル統計分析・更新・接続ガイドへの移動と復帰を確認。ガイドによるAPI書き込みなし。
- 最終ランタイム変更後の `npm run check` はprecheck / check / postcheckとも合格。`git diff --check` 合格。
- 実スクリーンショットで、通常時のMAP・観測、4K、スマホ縦、フォーカス中の斜めの光を目視確認。光のキャプチャはネイティブTab操作後の実アニメーションであり、静止位置を強制したものではない。

試験はインストール済みChrome、ローカルの実フロントエンド／画像、ビューポートとタッチのエミュレーション。観測データ・ログイン状態はローカルQAフィクスチャであり、実アカウントや実機器での動作とは区別する。新しい色・光の試験は本番CSPを適用し、外部HTTPS通信を遮断。

証跡: `artifacts/feature-theme-20260912/before/`、`after/`、`sensor-regression/`。各JSONに検証対象のSHA-256を記録。スマホのMAP再表示は実際の「ツール→地図ガイド」を操作する（デスクトップ専用の非表示ボタンを押す当初の試験記述を修正）。
