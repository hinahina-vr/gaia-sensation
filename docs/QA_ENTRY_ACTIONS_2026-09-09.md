# データ入口の全操作・関連遷移 再検証 — 2026-09-09

追記：以下は修正前の公開版 `2a4f513` の記録。製作者の追加指示「不具合直して」によるローカル修正と再検証は [QA_FOOTER_STORY_2026-09-09.md](QA_FOOTER_STORY_2026-09-09.md) に記録する。過去の失敗証跡は保持し、本番反映済みとは扱わない。

## 結論

**不合格：公開データ末尾の「ストーリーモードへ」は、ストーリー機能が未読込の初回操作では無反応。**

ユーザーの画像と同じボタンを本番でクリックして再現した。デスクトップのクリック・Enter・Space、390px幅のタップ、タイトルから「データを探索する」を経由する手順でも失敗する。ストーリーを先に一度開いてから同じボタンを押すと成功する。

対象は公開コミット `2a4f51385b69a0fda1ef285b0058acae7207640b`、Cloudflare Production `3b48ac87-9a85-4991-a3b4-f2dcf94bd208`、https://gaia-senseware.pages.dev/ 。アプリコードと公開版は変更していない。今回はテスト依頼として検証・回帰テスト追加を実施し、修正実装についてはユーザーに確認中。

## 原因と前回の見落とし

- `index.html` の `.data-journey-epilogue [data-novel-open]` にあるボタン。
- `novel-mode.js` は読込時に `[data-novel-open]` のクリック処理を登録する。
- `gaia-mode-loader.js` のクリック時遅延読込対象には、このボタンがない。
- `/#top` で入ると探索機能だけが読み込まれるため、このボタンにストーリーを開く処理がまだ存在しない。押した後も `GaiaModeLoader.isLoaded('story') === false`、`GaiaNovel` は未定義。
- 前回のQAはこのボタンからの初回遷移を検証していなかった。ストーリーの直URLやAPIによる事前読込は、この回帰を検出できない。

## 検証方法

実Chrome、1440×900と390×844（後者はタッチエミュレーション）。入口のケースごとに新しい隔離ブラウザコンテキストを使い、モードのopen/load APIを呼ばず、保存データも事前投入しない。本番の実レスポンスを使用し、モックなし。各ケースのクリック・キー、失敗時の画面状態、スクリーンショットを保存した。

本番DOMでデータ入口 `#intro-layer` の利用可能な操作を数えると、**ボタン11＋リンク26＝37件**。非表示の旧モード選択9個とその戻るボタン1個は、通常画面から操作できないためこの37件には含めていない。

## ストーリーの関連実操作

PC・スマホ幅とも、入口ボタンから初回開始して以下を実施し合格。

- CONFIGを開く、速度変更、動きを減らす、初期値に戻す、閉じる。
- SAVEの空きスロットへ実保存、本文をページ送りして先へ進む、ページ再読込、LOADで保存地点へ復元。スマホの本文分割を最後まで送ってから復元を比較。
- AUTOと早送りのON/OFF、JUMP一覧の開閉、LOGの開閉。
- LOGへの確認用コメントの入力と、実際のコメントMarkdownダウンロード。入力文字列が書き出されていることを確認。
- 全台本Markdownのダウンロード。現在の全step IDが含まれることを照合。PC版・スマホ版の各ファイルは161,870 bytes。
- 物語から入口へ戻り、問題の末尾ボタンを再度押すと表示できることを確認。これにより、クリック位置の問題ではなく、未読込時だけの登録漏れであることを確認した。

## 外部リンクの例外

- GCPのDOIリンクは、クリック後に `https://zenodo.org/doi/10.5281/zenodo.13981696` のタブが開くが、本確認環境では504 Gateway Time-out。別途HEADは403。参照本文は確認できていない。
- UNESCOは別タブが開くが、外部サイトの人間確認画面。作品側のクリック動作と参照先本文の検証を分け、本文確認済みとはしない。
- JAXAの「11列の説明」は初回自動試験でタブ待機がタイムアウトしたため、改めて実ブラウザからリンクをクリック。「Hayabusa2 LIDAR level 2 data product: time series topography」の本文と11列の表を表示確認。HEADも200。
