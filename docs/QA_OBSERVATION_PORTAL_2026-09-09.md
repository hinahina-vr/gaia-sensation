# 地図のタイトル演出・観測画面の質感とサイズ調整

## 依頼と対象

2026-09-09 の依頼：

- 地図の見どころ紹介を突然出さず、先に新しい「世界を観測する」タイトルを表示してからフェードインする。
- 地図の紹介と統計を一回り小さくする。
- 統計の「このグラフから／分かることを見つける →」がボタンの下にはみ出す画像について「こういうのも直して」。
- きらめき、フェードイン／アウト、押したくなる反応を加える。パステルカラーだけに限定せず、世界観のある色を使う。

実装対象は地図の導入・見どころ紹介と統計分析画面。統計側には独立した見どころ紹介がないため、分析画面の外枠を縮小した。タイトルの文言・追加場所は地図のみ。配色は「夜の地球を観測する窓」と解釈し、深い青、青緑、コバルト、紫、光の差し色で構成した。全ストーリー画面の一括改装という扱いにはしていない。

ローカル実装。基点は `cdc82c8ffd4fee607bd2d838ec3157b7095952d3`。この依頼ではコミット・push・デプロイを行っていない。前のフッターストーリーボタン修正と運用ルール更新は同じ作業ツリーに保持している。

## 変更

- `mode-entry-guide.js`、`app.js`：タイトル→紹介→任意の操作ガイドを別の表示段階にした。タイトルは約1.7秒の表示後にフェードアウトし、紹介が約0.65秒で現れる。スキップ、Escape、フォーカス移動、閉じてからの再表示、遅延処理の取消に対応。既読時の自動紹介抑制と「地図ガイド」からの再表示は維持。
- `mode-feature-intro.css`：地図の紹介をPCでは最大2320px／幅84vw・高さ84dvh、スマホでは幅92vw・最大高さ90dvhに調整。タイトルの光、カードの段階表示、ボタン上を流れる光、hover／押下の反応を追加。本文と元のイラストは保持。センサーの配色・サイズは変更していない。
- `statistics-game.css`：統計の外枠をPCで幅88vw・高さ86dvh、スマホで幅92vw・高さ90dvhに調整。周囲のパネルを新配色に統一し、グラフは白地のまま維持。小さい画面でも開いた直後にグラフが見えるよう、装飾的なヘッダーを圧縮した。
- `statistics-lab.js`：開閉をフェード化。閉じる時点で操作・フォーカス対象から外し、終了後に非表示にする。連続開閉で古い遅延処理が新しい画面を消さないようにした。
- `gaia-mode-loader.js`、`index.html`、`sensors/index.html`：変更したCSS／JSのキャッシュ識別子を更新。
- 動きを減らす設定では、装飾アニメーションと移動・フェードを停止する。統計計算、データ、保存形式、画像・音楽素材は変更していない。

## ボタンはみ出しの再現と修正

展示12「街と森、そのあいだ」→実際の「統計分析」ボタンで開いた。通常の縦横比では再現しなかったため、横に広く高さの短い条件も確認した。

| 修正前の表示サイズ | ボタン高 | 下の文字のはみ出し |
| --- | ---: | ---: |
| 3840×1080 | 66px | 34.59px |
| 2560×1080 | 66px | 20.11px |
| 1920×900 | 66px | 4.08px |

原因は、説明欄のグリッド行が縮む際にボタンが2行の文字より低くなること。説明欄の行とボタンを文字の実寸以上に保ち、必要な場合は説明欄の内部スクロールで全文に到達できるようにした。文字を小さくする、はみ出した文字を隠す、注意文を削る修正ではない。

再現記録は `artifacts/map-entry-title-20260909/cta-before-short/`。同条件を含む最終9画面では文字の境界がボタン内に収まり、注意文との重なりがないこと、ボタン中央で押せること、押して「分かること」が開くことを確認した。1920×900 の追加回帰も `cta-1920-final/report.json` で合格。再現した3条件すべてで修正を確認した。

途中で検出した問題も残している：

- 小さい320×568画面では、縮小後に初期グラフの見える高さが不足した。ヘッダーを調整し、最終の統計8画面で再合格。
- 古い入口テストは1.7秒後にガイドの有無を一度だけ判定していたため、新しいタイトルの後ろにある「戻る」を押そうとしてPC／スマホの2件が失敗した。テストを新しい実表示順に合わせ、タイトル→紹介→閉じる→地図から戻るという実操作で2件とも合格。元の32件一括実行を「全件合格」に書き換えてはいない。
- センサーの古いローカルテストは静的サーバーのAPI 404を受けてログイン画面へ遷移した。API fixtureをテスト内に明示し、最終の5ケースで公開地図の維持も検証した。
- 最終差分の確認で、フェード中の連続closeが非表示処理を取り消す問題を見つけた。同じ処理単位でcloseを2回呼び、操作不能な覆いが残ることを `repeated-close-before/` で再現。非表示タイマーを独立管理し、地図タイトル5画面・共有ガイド8ケース・PC／スマホの実際の地図往復2ケースで再確認した。

## 総合テスト・未確認範囲

総合ブラウザテストの最初の実行では画面の検証を通過したが、実行環境の通信制限による `ERR_NETWORK_ACCESS_DENIED` が5件あり、最後のエラー確認で失敗した。失敗記録は `contest-final/` に保持。同じコード・同じ判定を通信制限のない実行条件で再検証し、`contest-network/report.json` で合格した。console error、page error、未処理reject、404はいずれも0。既存の描画速度判定も合格（中央値59.88fps、基準55fps）。これはローカルChromeの既存テスト条件の値であり、実スマホでの性能保証ではない。

総合テスト後の追加変更は、上記の共有ガイドの連続close対策のみ。その影響範囲を `title-close-final/`、`shared-close-final/`、`entry-map-close-final/` で再検証し、最終ファイルのハッシュも照合した。GitHub上のCI実行・公開版のテストという扱いにはしていない。

本番への反映、本番での確認、実スマホ、外部AIサービスへの送信、実アカウント・実機センサーは今回の確認範囲外。配布ZIPは作成していない。前のストーリーボタン修正も含めてローカルまでであり、本番は未反映。

再実行はプレビュー起動後に `npm run check:observation-surfaces:browser`。追加の統計操作は `node scripts/check-statistics-game-browser.mjs http://127.0.0.1:4492 <証跡保存先>`、入口は `node scripts/check-entry-actions-browser.mjs http://127.0.0.1:4492 <証跡保存先>`。
