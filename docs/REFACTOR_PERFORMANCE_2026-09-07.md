# 表示・機能を維持したリファクタリングと性能改善

比較元: `c63e1d43369803a841c8c79d8a59b496cff72b67`。ローカル修正のみ。push・デプロイは行っていない。

## 変更内容

- `src/shared/number-format.js`: 日本語数値フォーマッターを桁数ごとに再利用。日本統計、ライブ観測、火災、惑星信号、国別CO₂履歴、統計ラボの重複処理を共通化した。観測値そのものはキャッシュせず、最新の値を毎回整形する。
- `src/shared/dom-updates.js` / `src/exploration/estat-exhibits.js`: 同じ値の属性・テキスト・スタイルの再代入を抑制。現在のDOMを比較するため、他のUI処理による更新も正しく反映する。描画内で取得済みのキャンバス寸法を投影計算に再利用。
- `app.js`: classic scriptの読み込み構成を維持したまま、観測数値のフォーマッターを再利用。
- `statistics-lab.js`: 年別地震件数を全件走査50回から1回の集計へ変更。対象期間・欠測処理・並び順・集計値は変更しない。
- `gaia-mode-loader.js`: 要求されたモードのclassic scriptを先読みし、通信の直列待ちを短縮。CSS→module→classic scriptの実行順序、モード単位の遅延読み込み、ロード完了判定は維持。未選択モードの先読みは追加しない。
- `index.html` / モード読み込み参照 / キャッシュキー検証: immutableキャッシュで旧コードが残らないよう、変更モジュールの参照バージョンを更新。
- `package.json` / 検証スクリプト: 共通処理・実行順序のテストを追加し、`npm run check`のpostcheckにも組み込んだ。

CSS、レイアウト、色、画像、音声、シェーダー、解像度、フレームレート設定、演出時間、公開データ、バックエンドは変更していない。

## 計測結果

同一PCの隔離した実Google Chrome、ローカルHTTP、CPUスロットリングなし。PCは1440×900、スマートフォン表示は390×844。後者は実機端末ではなく同一PC上のviewport比較。各展示の描画中3秒をCDPで計測し、変更後は2回の平均。実機・回線を跨ぐ普遍的な高速化率ではない。

| 表示幅 / 展示 | JS処理時間: 前→後 | 削減率 | マーカー関連DOM更新: 前→後 |
| --- | --- | --- | --- |
| 1440 / 21 人の移動 | 352.9→225.0 ms | 36.2% | 32,779→12,136 |
| 1440 / 22 宿泊 | 353.3→229.2 ms | 35.1% | 28,148→7,696 |
| 1440 / 24 年平均気温 | 248.4→120.9 ms | 51.3% | 17,374→493 |
| 390 / 21 人の移動 | 365.1→231.0 ms | 36.7% | 32,966→12,019 |
| 390 / 22 宿泊 | 369.6→231.2 ms | 37.4% | 28,007→7,696 |
| 390 / 24 年平均気温 | 276.6→138.7 ms | 49.9% | 17,374→493 |

描画は前後とも約60fps。改善は主に同じ描画内容を維持するためのCPU・DOM処理の削減。

通信待ちの比較では、JSリクエストごとに80msの遅延を加えた条件で、人物モードが578→154ms、物語モードが1,075→110ms。classic scriptの実行順序は同一で、先読み後の二重リクエストは0件。これは通信待ちを可視化する人工条件の値であり、実回線での所要時間を保証しない。

総合ブラウザーテスト: ローカルLCP 220ms、CLS 0、描画中央値59.88fps。変更前から入口は高速であり、LCP改善を成果として主張しない。

## 検証

- 数値整形170ケース: 符号、負のゼロ、小数、桁区切り、丸め、非有限値が従来の整形と一致。
- DOM更新: 180回の同値指定を1回の書き込みに抑制し、外部からのDOM変更後は再反映することを確認。
- モード読み込み: 未選択モードの遅延維持、同時呼び出しの共有、先読みと実行の分離、CSSとscriptの順序、二重取得なし。
- 参照コミットとのブラウザー比較: 日本統計10展示×2画面幅で、ラベル、ARIA状態、位置、地図形状、統計データ、時刻を固定した2Dキャンバスのピクセルが完全一致。全画面のアニメーションを含むスクリーンショットの完全一致を意味しない。
- 11データセットの記述統計結果×2画面幅も参照コミットと完全一致。
- `npm run check`、`npm run check:contest`、国別CO₂履歴の静的検証。
- 総合ブラウザーテスト: 入口、物語導線、ツアー、画面サイズ、モードの反復開閉、WebGLフォールバック・コンテキスト喪失。
- 日本地図GIS: PC/スマートフォンで展示15〜30の中心、拡大縮小、ホイール、ドラッグ、ピンチ、リセット、地点選択、自動巡回。
- 統計分析ガイド: 1440/390/320px。
- 国別CO₂履歴: 1440/390/320/844px、モジュール読み込み失敗時も選択年・出典・閉じる操作を維持。
- リアルタイム展示: 1440/390pxで表示識別、時刻、凡例、対象外展示への切替。

### 変更前からある旧テストの不一致

以下は今回変更していないテストとデータ契約の不一致。合格として扱わず、現行仕様の検証と参照コミットとの同値比較で変更による退行がないことを確認した。

- `scripts/check-statistics-lab.mjs`: 降水量の標本数を31と固定しているが、現データは237件。読み込む `statistics-lab-core.js`、データ、関連テストはすべて比較元から差分なし。このテストは今回変更したUI側の `statistics-lab.js` を読み込んでいない。
- `scripts/check-estat-exhibits-browser.mjs`: 旧展示番号16〜25と旧見出しを期待して待機がタイムアウト。現行の公的統計展示は21〜30。テストと展示カタログは比較元から差分なし。現行GISテストと今回の10展示×2画面幅の同値比較は合格。

旧期待値に合わせたデータ・表示の変更は行っていない。
