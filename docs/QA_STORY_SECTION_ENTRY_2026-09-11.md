# セクション後のフェードイン・オープニングの波音 — 2026-09-11

## 依頼と対象

ユーザー原文:

> ストーリーモード、セクションのあと、フェードインで文字だのUIだの表示されるようにして　いまなんか唐突
> あとオープニングの波の音の音量でかいので半分ぐらいにして

主担当の解釈: 本編と APEIRONCENE のセクション見出し後、本文・操作 UI が背景の切り替え完了後に自然に現れるようにする。白いプロローグの波音だけを約半分にし、BGM・遠くの声・ユーザーの音量設定は変えない。

対象は `codex/gaia-copy-motion-polish-20260904`、基点 `888c26b` のローカル作業ツリー。既存の改行、13:00 開始、温度自動再生、白い流体、エンディング入口などの未公開変更を維持。今回も push・デプロイ・配布 ZIP 作成は行わない。

## 変更

- `novel-mode.js` / `novel-mode.css`: 見出し中は周辺 UI を隠し、見出しと背景切り替えの完了後、本文を含む runtime・操作部・音量ボタンを 1,100 ms でフェードイン。通常のシーン境界、セクションスキップ、JUMP、時間区切り後を同じ入口に統一。文字送り自体は従来どおり。フェード中の Enter・セクションスキップは先頭文を飛ばさず、AUTO は表示後に再スケジュール。別のステップ描画・閉じる操作で残留タイマーを破棄。
- `true-end-mode.js` / `true-end.css`: 見出し・背景のフェード完了後に `interface` 段階を追加し、本文・LOG・スキップ・音量ボタンを 1,100 ms で表示。表示中は進行をロック。OS の動き低減、および本編の動き低減クラスでは追加の長い待機を行わない。スタッフロールからの既存 2.7 秒の入口演出は変更しない。
- `story-prologue.js`: 波のフィルターとマスターの間にゲイン `0.5` を追加。波だけを半分にし、遠くの声は以前と同じマスターへの接続を維持。マスター係数 `0.85`、ユーザー音量、3 秒の波音フェード、ミュート・復帰・キャンセル時の解放は維持。
- `gaia-mode-loader.js` / `index.html`: 対象 JS/CSS と親ローダーのキャッシュキーを更新。
- `scripts/check-story-section-entry.mjs`、`scripts/check-story-section-entry-browser.mjs`、`scripts/check-story-wave-volume-browser.mjs`、`package.json`: 静的回帰・実ブラウザー回帰と実行入口を追加。

本文、ページ区切りデータ、セリフ順、背景素材、音楽ファイルは今回変更していない。

実ブラウザーはインストール済み Chrome の headless 実行。ローカル配信に本番 CSP を適用し、外部サービスへの通信は遮断。クリック・タップ・キー入力を使用し、フェードは実時間で多フレーム測定。手動 SAVE / LOAD、実ファイルダウンロードも対象。後半への位置決めでは保存状態のテスト用 fixture とスタッフロール自身の animation.finish() を使い、検査対象のフェード自体は早送りしていない。

主担当が PC/スマホの中間フレームと表示完了画面も目視確認。最終実行は JavaScript 例外・404・CSP 違反なし。`after`、`audio-final`、`prologue`、`ending-entry` の対象ハッシュを最終作業ツリーと照合。`git diff --check` も PASS。

再実行: ローカルプレビュー起動後 `npm run check:story-section-entry:browser`。既存入口は `node scripts/check-story-white-prologue-browser.mjs --desktop-only` と `node scripts/check-ending-entry-fade-browser.mjs`。出力先は `GAIA_OUTPUT_DIR`、配信 URL は `GAIA_BASE_URL` で指定可能。

検証スクリプトの初回実行では、計測用 eval の CSP 違反、SAVE 後の閉じる操作の不足、動き低減を利用した位置決め後のクラス残留、スクリーンショット待機後の入力タイミング、モバイル AUTO が「次ステップ」でなく「次ページ」へ進む仕様、入口ガイドのタップ遮蔽を調整した。これらをアプリの修正完了と数えず、計測・操作を実利用に合わせて修正した後、最終対象版を再実行している。

## 制約・残件

- ローカル合格と本番反映は別。今回版は未公開で、本番確認は未実施。
- PC/スマホの viewport エミュレーションであり、物理スマホ・Safari・実機スピーカーでの主観的な聴感評価ではない。音量は実音声処理の PCM 出力比で検証。
- 既存の「高さの低い横向き画面で、本編の操作部が重なる」問題は未解消。今回の縦向き表示・フェードの検証を横向きレイアウト全体の合格と解釈しない。別途、短い横向き画面の操作配置調整と回帰確認が必要。
