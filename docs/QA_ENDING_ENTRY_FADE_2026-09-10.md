# スタッフロール後のフェードイン延長

## 依頼と対象版

2026-09-10の依頼原文: 「ここ、ブラックアウトしてから　次のシーンに行くまで早いので、いまの3倍ぐらいの尺でゆっくりフェードインして」。添付2画面に対応する、スタッフロールの「世界の続きを紡ぐ」からAPEIRONCENEの最初のAIVA会話へ入る遷移が対象。タイトルからの白いプロローグとは別の入口。

基準コミット `888c26b623151205f6b8ecf9f77951dbc9a425ae` に先行する章BGM・白いプロローグのローカル変更と今回の変更を重ねた作業ツリーを検証。コミット・push・デプロイは未実施。

## 変更

- `novel-mode.js` の `STAFF_ROLL_EXIT_REVEAL_MS` と `novel-mode.css` の黒幕のフェード時間を、900msから2700msへ同期して変更。フェードイン部分を3倍にした。
- 暗転・黒画面の保持・描画準備待ち・背景だけを見せる間・台詞UIの表示順は維持。次の映像が現れきるまで台詞を開始しない。動き低減設定では従来どおり短い遷移を維持。
- `gaia-mode-loader.js` と `index.html` の読み込みキーを更新。`scripts/check-true-end-transition.mjs` の時間契約を更新し、`scripts/check-ending-entry-fade-browser.mjs` と `npm run check:ending-entry-fade:browser` に実操作の回帰試験を追加。

## 検証結果

証跡: `artifacts/ending-entry-fade-20260910/`。インストール済みChrome、本番と同じCSPを適用したlocalhost:4492、分離した保存領域を使用。最終シーンの検査用セーブから入り、準備操作としてクレジットの既存アニメーションだけを `animation.finish()` で終了させた。その後のThanks表示を待ち、対象ボタンは実クリック／タップ、暗転とフェードは実時間で検証した。全編を通読した試験・実ユーザーの保存データを使った試験ではない。

- 変更前 `before/report.json`: 同じボタンの実操作でフェードを900.30msと計測し、短い表示を再現。
- 変更後 `after/report.json`: PC 1440×900で2700.40ms、スマホ幅390×844で2700.20ms。黒幕の不透明度が滑らかに下がり、フェード中は会話UIが非表示、台詞も未開始であることを確認。途中のPC画像と完了後のスマホ幅画像を目視確認。
- 動き低減の390×844も合格。完了後の黒幕除去、黒幕の重複なし、手動セーブ不変、会話ボタンの操作可能状態、LOGから全文Markdownの実ダウンロードと本文を確認。
- ブラウザ実行エラー・404・CSP違反は0。`npm run check` 全体合格（`npm-check.log`）、`git diff --check` 合格。
- ブラウザ試験の5対象ファイルのSHA-256と完了時の作業ツリーを照合し、全件一致。主要ハッシュ: `novel-mode.js` = `42ce9e69e358ad9ffd67dd882d18fb9e7715d3f4d8a51286815ab4e8e0e9155a`、`novel-mode.css` = `e2cc3c280824dfbde5669013a16314687bab007d4845b92c0f85aae0d8bbf073`。

2.7秒は映像のフェードイン部分の時間。ボタン押下からの総時間はGPU等の描画準備待ちを含むため環境で異なり、一定3.285秒で遷移全体が終わるという意味ではない。
