# 未確認のSNSアカウントを公開リンクに設定しない

依頼: 実在するオーナーのアカウントだと確認できていないGitHub等のリンクは「なし」にする。

## 原因と変更

ローカル確認用サーバー `scripts/serve-sensor-platform-qa.mjs` の初期プロフィールに、青猫名義の仮のX・GitHub・Instagram URLが入っていた。画面側はAPIで返された非空のURLをそのまま公開リンクとして表示していた。

- 初期プロフィールの `xUrl`、`githubUrl`、`instagramUrl` をすべて `null` に変更。確認のないアカウントを推測で作らない。
- `scripts/check-sensor-profile-map-browser.mjs` も、架空のアカウント名を書き込む試験から、未登録の空欄を保存・検証する試験へ変更。試験後のプレビューに仮URLを残さない。
- `scripts/check-sensor-public-profile-browser.mjs` の初期リンク期待値を未登録に更新。
- 新規 `scripts/check-sensor-unset-socials-browser.mjs` で公開表示、空欄保存、再読み込み後の未登録状態を確認。
- 起動中のローカル4447・4501番ポートにも、既知の仮URLであることと確認用ユーザーIDを照合したうえで、3フィールドだけを `null` に更新した。各プロフィールのその他の項目は変更前後で完全一致を確認。デバイス・位置・アイコン・名前は変更していない。

既存の画面処理は、URLが未登録ならリンクボタンを出さず「SNSリンクは登録されていません。」と表示する。そのためアプリのCSS/JSや本番バックエンドを変更する必要はなかった。ユーザーが後から正しいURLを登録する機能は維持している。

## 再現と検証

変更前は現在のローカル4447の公開プロフィールを実際に開き、3個のリンクが存在することとリンク先を記録した。`artifacts/sensor-unset-socials-before/report.json` と `1440-profile.png`。

最終結果:

- **実際に表示しているローカル4447で4条件合格**（1440×900、390×844、320×568、844×390）。公開カードとプロフィールのリンク0件、未登録文言、横はみ出しなし、戻るとフォーカス復帰、フォーム3欄が空、保存→再読み込み→公開プロフィールでも空のままであることを検査。`artifacts/sensor-unset-socials-local-verified/report.json`。
- **新しい初期データで公開プロフィール試験4条件合格。** 別途起動した確認用サーバー4498で、実描画・戻る・Esc・閉じる・reduced motionを検証。`artifacts/sensor-public-profile/report.json`。
- **プロフィールと地図の既存回帰試験3条件合格**（1440、390、320px）。専用の一時サーバー4517で、空のSNS値を保存した後もnullであること、関連するプロフィール・画像アップロードの既存チェック、フォーム・公開位置操作を確認。`artifacts/sensor-unset-socials-profile-map/report.json`。画像アップロードの既存チェックは画像内容の一致までを保証するものではない。
- PC・390pxの最終プロフィール画像を開き、ボタンが消えて未登録の文言になっていることを確認した。
- 最終3レポートはいずれも合格。実行時エラー0。
- `npm run check`、変更した4スクリプトの構文検査、対象ファイルの `git diff --check` は合格。
- 最後に4447・4501の公開APIを再取得し、確認用オーナーと4デモオーナーのSNS値がすべてnullであることを確認。

新規試験の初回は、プロフィール編集後にセンサー未選択の地図へ戻るとプロフィールボタンが存在しない、という試験側の前提でタイムアウトした。アプリの正式な `#map/sensor=sensor_browserqa` 深いリンクから対象を選択して再検証し、合格した。アプリのクリック処理を代替発火して合格させていない。

`sensor-unset-socials-local-verified/report.json` には、確認用サーバーのソースおよび検証したセンサーHTML/JSのSHA-256を記録。

## 範囲と注意

今回の変更はローカル確認用データ・試験のみ。本番のプロフィールを変更・削除したものではなく、push/deployもしていない。実機スマホ・Safari/Firefox・実SNSアカウントの所有権・公開配信は未検証。配布ZIPは作成していない。

既存4447・4501のプロセスは他の確認用データを保持するため再起動しておらず、現在のプロフィール値だけを変更した。これらの古いプロセスで `/__qa/reset` を使用する場合は、先に更新済みサーバースクリプトで起動し直すこと（古いプロセスは旧初期値を保持しているため）。新規起動で初期リンクが空になることは4498の試験で確認済み。
