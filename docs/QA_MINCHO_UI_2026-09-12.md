# 明朝体の統一と読みやすさの検証

## 依頼と対応

ユーザー原文：「地図メニュー、ゴシックで萎えるんだよな　1枚目のフォントにできる？あと他にもゴシック乱発されてて統一感ないので、視認性の高い明朝で統一してほしい」。添付1枚目は「森と水のつながり」、2枚目は展示選択メニューとホバー説明、3枚目は「何を見る？／色の意味／押すと」の説明パネル。

地図だけでなく、各モードの見出し・本文・メニュー・入力欄・統計グラフの日本語を同じ明朝系統に揃える依頼として対応。英数字のコード・IDなどの等幅表示と、記号専用のフォントは維持した。

変更前のChromeで参照タイトルの実描画フォントを取得し、1440／3840／390pxのすべてで `Yu Mincho Demibold` を確認。メニュー・説明文に別のゴシック用トークンが使われていたため、既存の游明朝スタックを共通化した。外部フォントの通信や新しいフォントファイルは追加していない。

## 変更

- `typography.css`：日本語・UI・等幅内の日本語フォールバックを一元化。メインとSENSORのHTMLから初期読み込みし、遅延モードにも共通設定を適用。
- `styles.css`、`opening.css`、`sensors/sensor-platform.css`：重複したフォント設定を撤去。各モードCSSに散在した等幅指定を共有トークンに統合し、日本語がゴシックへ戻る経路を除去。
- `character-mode.css`、`novel-mode.css`、`ecologies-exhibit.css`、`metric-legend.css`、`sensors/sensor-onboarding.css`：固定ゴシック指定を明朝へ変更。
- `map-ui-grid-polish.css`、`map-unified-dock.css`、`statistics-workspace.css`、`statistics-game.css`、`gx-mode.css`、`story-temperature.css`、各観測展示CSS：数値・単位・操作ラベルも揃えた。ボタン小見出しは9pxとし、先行依頼の固定寸法を維持。
- `app.js`、`statistics-lab.js`：Canvasの数値・単位・軸・凡例も共通の明朝で描画。計算・データ・保存形式は変更していない。
- `map-exhibit-categories.css`：英字のNMHC／COD／BOD等が明朝化で横に広がる症状を確認し、セル幅に合わせた文字サイズ上限を設定。1024px幅で透明な数値パネルのドラッグ領域がメニューの日本タブを遮る問題も、メニュー展開中にその領域の入力を無効化して修正。
- `space-mode.css`：目視で見つかったPCの見出しと説明の重なりを修正。上下別の行に配置し、長い説明はその行内をスクロール可能にした。スマホ配置は変更していない。
- `gaia-mode-loader.js`、両HTML：変更資産のキャッシュキー更新。新しい回帰スクリプトを追加し、既存2スクリプトに証跡出力先指定を追加。

対象はHEAD `9fbd901b68faebaf6148db6e18cdbcb50fa1c778` 上の未公開作業ツリー。先行する未コミット変更を保持。コミット・push・デプロイ・ZIP作成はしていない。

## 確認範囲と残件

インストール済みChrome、本番CSPを適用したローカル画面での検証。外部フィードは遮断または保存データ、SENSORのアカウント／観測値はローカルAPIフィクスチャ。SPACE／GXは対応するシーンAPIで初期化した後、実画面・操作を確認した。実機スマホ・他OSの代替フォント・他ブラウザー・実アカウント・実センサー・本番反映後の確認ではない。

統計で確認したのは条件保存と再読込であり、統計ファイルの書き出しではない。今回ダウンロードまで確認した書き出しはストーリーの全台本Markdown。途中の進捗で両者をまとめて「統計分析の操作・書き出し」とした表現は、この記録の範囲に訂正する。登録・プロフィールの本番保存やESP32書き込み、AIへの外部送信は行っていない。

先行記録にあるストーリー小窓の年表示領域の2pxはみ出し、旧12→13手動操作の元症状未再現は、本件で解決した扱いにはしない。今回の明朝統一・地図の通常表示／メニュー・保存等の合格範囲と区別して継続保持する。本件の公開は未実施。
