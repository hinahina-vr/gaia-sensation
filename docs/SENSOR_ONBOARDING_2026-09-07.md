# センサー登録・接続導線の再設計 — 2026-09-07

## 対象

`63ec6ffdb495256fde6ad1e58c7c963954c741c3` を基点とするローカル作業ツリー。今回の対象は `sensors/index.html`、`sensors/sensor-platform.js`、新設の `sensors/sensor-onboarding.js` / `.css`。既存の未コミット変更は維持。push・deploy・ESP32への書き込みは行っていない。

ユーザー報告は、接続ガイドとコード発行後の説明がつながっていないこと、登録済みESP32を突然Codexへ指示しても準備がわからないこと、計測項目の巨大な一覧による登録フォームの使いづらさ。

## 変更

- `#devices` を入口に、新しい機器の準備と登録済み機器の確認を分離。コード表示・期限・接続確認も同じ一覧内へ統合。
- `#guide` と既存の項目アンカーは維持。ガイドからマイセンサーへ進み、同じタブ内の往復ではフォームと接続コードを保持する。
- Codexへの依頼文を「準備」「USB接続」「登録済み機器の診断」の3種類に分離。PC・作業フォルダ・固定版ソースURL・必要ファイル・USBプロトコルと115200 baud・権限不足時の停止条件を含めた。コードやWi-Fiパスワードは依頼文に埋め込まない。
- 既存機器の案内は診断から始め、勝手な削除・再登録・BOOT初期化・再書き込みを禁止。既存認証を保持したWi-Fi変更は変更前に確認する。
- 登録は「観測点について」「公開する地域」に整理。選択済みチップ、プリセット、検索、折りたたみを追加。最大16項目・既存端末の項目変更・公開POI・地域コードは維持。
- 初期3項目は配布ファームウェアの模擬データであることを明記。項目選択だけで実測にはならない。
- 実装確認で、コード発行時には `device_pairing_codes` の下書きのみが作られ、`pairDevice` で初めて端末が作られることを確認。旧説明の「期限切れなら端末削除」を撤去。期限切れは接続済みか確認後、同じ下書きを確認して再発行できる。
- 一覧に同名機器があるだけでは新しい接続の成功と断定しない。詳細のONLINE・最終更新・観測値、必要ならDevice IDで確認する。
- 接続コードはメモリ／表示DOMだけで保持。localStorage・sessionStorageに保存しない。期限切れ・ログアウト・表示終了で消去し、再読み込みで再表示できないことも明記。

- ソースの既存固定版 `de7e661dbccb151a963d755f5772db53e7d419f9` を維持。機種・プロトコルが一致しない既存ESP32への自動上書きは案内していない。
