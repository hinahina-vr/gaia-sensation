# SOUND一覧のアイコン・文字バランス

依頼原文: 「アイコン文字の大きさ文字の位置　バランス悪い気がする」

直前に圧縮したSOUNDの星座一覧への指摘として対応。ローカル変更のみ。基点は `db63742c12f0ec9a7538ba7073d6029d384e5e7f`、先行する横画面・全曲解放・本編配曲・OP候補の変更を保持。push・デプロイなし。

## 原因と変更

- 曲名の描画に仮想の110単位の高さ、旧来の上方向22px補正、キャンバス下余白18pxが残り、星座とは異なる位置に文字が配置されていた。文字の実画素の中心は星座枠の中心より最大13.69px上だった。
- 曲名によって仮想枠と実際の筆画の占める範囲が異なり、同一画面でも見た目の文字高に差があった。4Kの全12曲では43〜55px、921px幅では11〜22px。
- `sound-mode.css`: 星座と曲名で中心位置を共有。番号の大きさ・番号までの間隔・星座の大きさを同じ組の変数で決定。番号を近づけ、通常時と曲名表示時で番号の位置を維持。
- `sound-constellation.js`: 実際の筆画の外接範囲から文字の大きさ・中心を計算し、全曲を統一。長いタイトルには残る11曲の44px以上の操作領域を確保。補助の波形線は文字より下に収めた。文字を形成する流星・星の演出は維持。
- 一覧自体の高さ `clamp(96px, 6.5vw, 160px)` は維持。920px以下のモバイル縦一覧の書式は変更しない。
- `gaia-mode-loader.js` と `index.html` の対象キャッシュキーを更新。`package.json` に `check:sound-balance:browser` と新テストの構文検査を追加。

## 合格した検証

- `scripts/check-sound-rail-balance-browser.mjs --before` および通常実行: 5画面幅×全12曲。変更前の上ずれを再現し、変更後の文字高・中心・番号との空間・左右の余白・全12曲の操作領域・一覧の高さを確認。確定フレーム比較には動きを減らす設定を使用。
- `scripts/capture-sound-morph-prototype.mjs`: 通常アニメーションで全12曲の文字形成、星→線の順序、移動する星、高速なフォーカス切替、実再生、PC/4K/スマホ、動きを減らす設定の停止を確認。
- `scripts/check-sound-compact-rail-browser.mjs`: 3840・1920・1440・1024・921・920・390・320px幅の8条件。従来どおりの圧縮高さ、操作領域、通常の文字形成、収まり、スマホでの全12曲へのスクロール到達を確認。
- `scripts/check-sound-browser.mjs`: 全12曲のネイティブ選曲・実音源・音声解析、PC/スマホのプレイヤー・ジャケット・銀河描画の既存回帰検証。
- `npm run check`: precheck / check / postcheck 全て合格。
- `git diff --check`: 合格。
- 4Kの英語長名・日本語短名、1920pxの英語長名、1440pxの日本語名を実スクリーンショットで目視確認。

証跡は `artifacts/sound-rail-balance-20260912/` の `before/`、`after/`、`normal-motion/`、`regression-geometry/`、`full-sound/`。before/after と geometry の JSON は対象ファイルのSHA-256を持つ。新しい画素比較テストは本番CSPを適用し、外部通信を遮断。通常モーションの既存キャプチャテストはローカルブラウザの演出確認であり、本番CSPでの検証とは区別する。
