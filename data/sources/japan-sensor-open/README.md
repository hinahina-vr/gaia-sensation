# 日本の水質・気象観測データ（展示32〜43）

このフォルダは公開元から取得した応答の保存用。表示用JSONは `data/japan-{marine,river,lake,weather}-*.json`。元の値、注記、地点コード、名称、座標を保持し、未観測地点・欠測値を補間しない。

## 環境省

出典：[水環境総合情報サイト・公共用水域水質測定データのダウンロード](https://water-pub.env.go.jp/water-pub/mizu-site/mizu/download/download.asp)。[年間値ファイルの説明書](https://water-pub.env.go.jp/water-pub/mizu-site/mizu/download/kousui/kousui_y_manual.pdf)を参照。

2020〜2024年度の生活環境項目。海域は既存 `../japan-marine-cod/` の2026-09-08取得ZIPをそのまま再利用。河川・湖沼は2026-09-09に公開ダウンロードフォームの処理で取得した。`p_kosui_y02`、`nendo=YEAR and suiikicode < '600'`、CSV形式。公開元の `RLSCODE`（1：河川、2：湖沼、3：海域）で区別する。

- `PH_MIN` / `PH_MIN3`：pHの年度最小値。主表示に使う。
- `PH_MAX` / `PH_MAX3`：pHの年度最大値。選択地点の補足表示。最小・最大から平均を作らない。
- `DO_` / `DO_3`：DO（溶存酸素量）の年度平均値、mg/L。COD・BOD・底層DOを代用しない。
- pHは酸性・アルカリ性の無次元の尺度。登録項目の表示単位は `pH`。説明書の一括した単位欄にあるmg/LをpHへ当てはめない。
- 数値の空欄・99999は欠測。`ND`・`<`・`>`は数値補助列が空欄や99999でも注記付きとする。0は有効な0として扱う。
- `PREFCODE + SUIIKICODE + CHITENCODE`を2・3・2桁で結合した地点コードを年をまたぐキーに使用。年内システムID `ZETTAICODE`も監査用に保存。
- JGD2000の元座標を年度ごとに維持。名称・採水条件・地点は変更され得る。測量精度の表示や基準達成判定は行わない。

## 気象庁

出典：[過去の気象データ検索](https://www.data.jma.go.jp/stats/etrn/)。例：[東京・年ごとの値](https://www.data.jma.go.jp/stats/etrn/view/annually_s.php?prec_no=44&block_no=47662&year=&month=&day=&view=)。各地点の出典URL・官署番号と取得ファイル名は `manifest.json` に記録。

2026-09-09に札幌〜石垣島の38気象官署の「年ごとの値・主な要素」を取得し、2020〜2024年だけを抽出した。全国の全アメダスや全自治体を網羅したデータではない。最新年を名乗らず、比較期間を2020〜2024年に揃えた保存版。

| 登録指標 | 使用する元の列・集計 | 表示単位 |
| --- | --- | --- |
| `temperature` | 日平均気温の年平均 | °C |
| `humidity` | 相対湿度の年平均 | %RH |
| `pressure` | 現地気圧の年平均。海面更正気圧ではない | hPa |
| `rainfall` | 降水量の年合計。降雨強度ではない | mm |
| `wind_speed` | 風速の年平均。最大瞬間風速ではない | m/s |
| `solar_irradiance` | 全天日射量の日積算量の年平均を24時間平均相当へ換算 | W/m² |

日射の換算は元のMJ/m²（日積算量）の年平均 × 1,000,000 ÷ 86,400。元の文字列・単位を `sourceText` / `sourceUnit` に保存し、画面にも表示する。日中の瞬時値ではなく、夜間を含む24時間平均相当。38地点中7地点は日射が欠測で、他の地点の値を転用しない。

欠測・無資料の記号は保持。`)`付きの準正常値、`]`付きの資料不足値などは、元の文字列を保持したまま数値をnullとして分析対象外にする。気象庁による元統計の訂正は、この固定スナップショットに自動反映されない。

地点の座標は取得時点の[気象庁観測地点表](https://www.jma.go.jp/bosai/amedas/const/amedastable.json)の度・分を十進度へ変換。観測点の現在の位置であり、過去の移転前の座標を復元していない。この制約は画面の読み方にも記載。官署名が一致するtype Aの観測地点を使い、行政庁や県庁の代表座標で置き換えない。

石垣島はAMeDAS地点コードの先頭94と過去データ検索の地域番号91が異なる。`jma-47918-91.html`が使用した正常な応答。`jma-47918.html`は初回の地域番号94による「ページを表示できませんでした」という応答を未加工の取得記録として保持しているが、値の抽出には使わない。

## 利用条件・加工主体

[環境省の利用条件](https://www.env.go.jp/mail.html)と[気象庁の利用条件](https://www.jma.go.jp/jma/kishou/info/coment.html)を2026-09-09に確認。両サイトが示す公共データ利用規約1.0に従い、出典リンクと「GAIA SENSEWAREが抽出・加工」を表示する。官公庁がこの展示を作成・承認したと表示しない。ロゴ・写真・地図画像は取り込んでいない。既存資料についての公開判断を今回の公開許可に流用しない。

ESP32登録指標との対応は物理量と単位の対応であり、同じ観測条件・精度・校正を保証しない。リアルタイムの観測や安全性・長期変化・原因の判定ではない。

## 再現と検証

リポジトリのルートで実行（Python 3標準ライブラリのみ）。

```text
python scripts/build-japan-sensor-open-data.py --fetch
python scripts/build-japan-sensor-open-data.py
python scripts/build-japan-sensor-open-data.py --check
python scripts/check-japan-sensor-open-source.py
npm run check:japan-sensor-open
```

`--fetch`だけがネットワークへ接続する。取得済み応答を再利用し、上書きしない。別時点へ更新する場合は元応答を残して新しい版を作る。オフラインビルドは原応答と既存海域ZIPのSHA-256を検証し、公開JSONを再生成する。`--check`は保存済みJSONとの一致を確認する。

表示データは12展示合計84,184地点・期間・指標レコード。実測数値82,471、欠測1,636、注記付き77。環境省83,044レコードと気象庁1,140レコードを、生成処理と別の読み取り経路で原資料へ照合する。物理的に異なる84,184地点があるという意味ではない。
