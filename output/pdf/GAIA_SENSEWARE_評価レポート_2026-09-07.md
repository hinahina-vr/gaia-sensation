# GAIA SENSEWARE
## システム評価と事業化に向けた提言

経営戦略・事業開発・ITアーキテクチャの統合評価

2026年9月7日　経営判断用　独立評価レポート

### 経営判断の要旨

GAIA SENSEWAREは、公開データを物語・光・音・操作へ翻訳する体験作品として、継続投資に値する。一方、公開データの許諾整理が未完了であり、学習効果、支払意思、継続運用能力の証拠も不足している。**現時点の推奨は、権利上の未解決事項を先に閉じ、教育・展示に用途を絞って90日間の実証へ進むこと**である。商用本展開や行政の意思決定基盤への拡張は、その実証結果を待つ。

| 判断対象 | 推奨する判断 | 理由 |
| --- | --- | --- |
| 作品と中核技術への投資 | 継続 | 30展示、物語、出典・加工の説明が接続し、体験設計の資産がある |
| 現在の公開データ | 即時に公開可否を再確認 | 既存監査の未解決項目に対応するデータ・画像を公開URLから取得できた |
| 次の事業検証 | 教育・展示に限定して実施 | 既存体験との整合性が高い。ただし需要があるという実績は未確認 |
| 大規模な商用サービス化 | 条件が整うまで保留 | 利用許諾、効果、採算、運用品質を先に検証する必要がある |

### 最初の意思決定

今週決めるべきことは、新機能の追加ではなく、①許諾未確認データの扱い、②最初に価値を検証する利用者と場、③90日間の責任者と工数上限である。全面的なフレームワーク移行や独自AI基盤の構築は、この期間の優先投資に含めない。

本書は、ご指定のコンサルティング視点による独立評価であり、McKinsey & Companyまたは他のコンサルティング会社の公式見解ではない。実在の外部コンサルタントによる共同監査を実施したものでもない。法的な最終判断や第三者認証を提供する文書ではない。

根拠と範囲：公開画面・公開HTTP応答、ローカル実装、既存運用資料、今回の診断結果。事実と提案を区別し、検証対象の版と未確認事項を11ページに記録した。

# 01 総合評価

### 体験の完成度と事業の準備度を分けて判断する

本システムを一般的な業務SaaSと同じ尺度だけで評価すると、物語とデータ表現の価値を見落とす。反対に、映像の完成度だけで商用提供を判断すると、許諾・学習効果・運用責任の不足を見落とす。以下は教育・展示での外部提供を想定した定性的評価であり、業界ベンチマークや認証点数ではない。

| 評価領域 | 判定 | 確認できた根拠と残る課題 |
| --- | --- | --- |
| 独自の体験価値 | 強み | MAP 30展示と物語の実画面を確認。数値の説明と演出を接続できる。競合に対する優位性は未比較 |
| データの説明可能性 | 強み | SOURCE・DERIVED・SCENARIO、モデル値・保存値などの区分がある。利用者の正しい理解は未測定 |
| 顧客適合と収益性 | 未実証 | 教育・展示との整合性は高いと判断。利用者調査、売上、継続率、獲得費用の資料は未確認 |
| 品質保証と変更容易性 | 基盤あり・要改善 | CIと多様な検査が存在。ただし旧仕様の統計テスト失敗と説明資料の陳腐化を確認 |
| 権利と外部提供条件 | 最優先是正 | 既存監査に未完了事項があり、該当する公開データ経路も残る。テスト合格で代替できない |
| セキュリティとプライバシー | 設計配慮あり・保証未了 | セッション保護、CSRF対策、取得情報の抑制を確認。BYOKと公開位置情報は用途別の再評価が必要 |
| 運用と拡張性 | 小規模運用の基盤あり | D1集計表・ポーリング抑制・運用文書がある。現在の本番負荷と復旧能力は未計測 |

### 評価の確度

公開応答、画面、今回のテスト結果は直接証拠として扱う。過去のD1改善効果や性能測定は既存記録として扱い、今回の再測定とは呼ばない。需要、教育効果、支払意思、必要工数は検証対象の仮説である。未実証の領域を「低品質」と断定せず、次の投資判断に必要な証拠として明示した。

意思決定上の含意：表現の追加投資だけでは、外部提供の条件は満たせない。次の開発単位には、機能だけでなく許諾、利用者への効果、運用・回帰検査を含める。

根拠：E1、E2、E3、E4、E5、E6、E7、E8。識別子の対応は12ページ。

# 02 最初の用途を教育と展示に絞る

### 提供する価値はデータを読み解く体験

最初の提供仮説は、学校・大学・科学館等における、地球データの読み方を体験する短時間プログラムとする。理由は、物語による関心喚起、データへの直接操作、出典と加工の説明が既に同じ作品内に存在するためである。これは実装との適合性に基づく提案であり、市場調査で需要を確認した結論ではない。[E1、E3、E6]

| 選択肢 | 既存資産との適合 | 主な追加要件 | 判断 |
| --- | --- | --- | --- |
| 学校・科学館の体験教材 | 高い | 学習目標、進行台本、共有端末設定、理解度評価 | 最初の実証先 |
| 企業の環境教育・展示 | 中程度 | 商用利用条件、主張の検証、契約、会場運用 | 権利整理後の第2候補 |
| 行政・企業の判断用ダッシュボード | 低い | 精度保証、追跡可能な分析、業務連携、SLA | 当面は対象外 |
| 一般消費者向け有料会員制 | 不明 | 継続利用の理由、決済、顧客獲得、サポート | 需要確認まで保留 |

### 実証パッケージの提案

「20分の地球データ探究」を仮の単位とする。短い導入の後、権利整理済みの3展示だけを選び、比較・出典確認・気付きの言語化までを一連の課題にする。主な利用者は学習者、採用を決める相手は教員・展示担当者であり、両者を別々に評価する。

初回はログイン、ESP32、BYOK（利用者自身のAPIキーを使う方式）による外部AI分析を必須にしない。進行用資料、端末・回線の事前確認、終了時の設定リセット、障害時の代替進行をセットにする。全30展示や物語全編は残し、実証の評価対象だけを絞る。

### 有償化を判断する順序

まず、採用候補者5名程度に、利用場面・準備負荷・予算決裁者を聞く。次に2つの現場で実証し、学習者の理解と担当者の再利用意思を確認する。その後に、初期設定費・開催支援費・保守費を分けて見積もる。価格、市場規模、売上見通しを現時点で数字に固定しない。

非商用の教育利用と企業の販促・有償提供では外部APIの条件が変わり得る。たとえばOpen-Meteoの無料APIは非商用を条件とするため、企業案件の受注前に契約条件を確認する。[W3]

### 次に検証する体験上の問い

視覚表現は関心を引く一方、光の強さや点の密度が何を意味するかを理解できるかは別問題である。3展示の各課題に「何を比較するか」「元の値か計算値か」「この図だけでは言えないこと」を1つずつ置き、終了時に利用者自身の言葉で説明してもらう。

MAPを単独で学習に使える入口を維持し、物語の読了を条件にしない。自動巡回や演出は鑑賞に有効だが、比較の途中で選択が変わらないよう、学習用の停止状態と手動操作を明確にする。

学校・公共展示への提供前に、キーボードのみの操作、読み上げ順序、拡大表示、コントラスト、動きの停止を実査する。WCAG 2.2を評価基準にするが、今回の画面確認だけで適合を宣言しない。[W4]

# 04 データ権利の未解決事項を先に閉じる

### 既存監査の指摘と現在の公開経路が一致している

既存の外部データ監査は、GOSAT、UNESCO、GBIF、未使用のJAXA由来PNGを未解決項目としている。今回、公開JSON内にGOSAT復元データ等の識別子が存在することと、該当PNGがHTTP 200で取得できることを確認した。個別の許可書は提示されておらず、是正済みとは評価できない。[E1、E4]

| 優先対象 | 今回確認した事実 | 提案する対応と完了条件 |
| --- | --- | --- |
| GOSAT由来の格子・復元値 | 公開JSONに関連識別子が残る。公式条件には第三者配布の禁止と商用利用の事前相談がある | 加工物の公開可否を提供元へ確認。書面確認まで対象データの公開継続を判断し、許諾または適法な代替へ |
| UNESCO世界遺産データ | 公開JSONにunesco-whcが残る。公式FAQは再掲載の事前書面許可を求める | 許可の取得、または対象部分の公開除外・代替。判断記録と公開物を照合 |
| GBIF観察記録 | 取得スクリプトにレコードのlicense・datasetKey等の保存がない | 権利情報付きで再取得・照合。用途に合わない記録を除外し帰属を保持 |
| 未使用JAXA由来PNG | jaxa-fnf-riau.pngを公開URLから取得できた | 取得元と許諾を確定、または配布対象から除外。未使用でも公開経路を確認 |

GOSATの加工物に対する具体的な法的評価は、ここで断定しない。提供元との確認事項として扱う。UNESCO条件と合わせ、公開継続の判断をオーナーと権利確認担当者が行うべきである。[W1、W2]

### ダウンロードボタンの有無では判定しない

画面内のCSV等の書き出しを廃止しても、表示用JSONや画像がURLから取得可能なら、その配信自体の条件確認が必要である。今回の公開JSON取得はこの点の直接証拠になる。これは直ちに違法性を断定するものではない。[E1、E4]

データ台帳には、元提供者、版、取得日、ライセンス、加工内容、商用可否、再配布可否、許可証の所在、公開ファイルを結び付ける。CIは台帳の「存在」だけでなく公開ファイルとの一致を検査する。Open-Meteo等の用途条件も案件ごとに照合する。[W3]

# 05 現行構成を維持して配信と責務を整理する

### 構成の選択は現段階に合っている

ブラウザ標準APIを中心とした作品本体と、Cloudflare上のAPI・任意センサー拡張を分ける構成は、閲覧者全員にアカウントやデータベース処理を要求しない。モード単位の遅延読込、共通数値整形、描画更新の抑制も既に実装されている。全面的な再実装を優先する根拠はない。[E3、E5、E7]

| 現在のデータ経路 | 主な役割 | 次に明確にする責任 |
| --- | --- | --- |
| 取得スクリプト → 版管理JSON → ブラウザ | 過去データ、統計、宇宙展示 | 版、権利、更新日、公開対象の判定 |
| 外部提供元 → Pages API → ブラウザ | ライブ系の取得・キャッシュ・退避 | 有効期限、上流障害、API契約、呼出量 |
| 外部提供元 → ブラウザ | 全球モデル値・地震等の直接取得 | 提供元別の利用条件と端末側の失敗表示 |
| センサー → API → D1 → センサー画面 | 任意の公開観測参加 | 認証、位置公開、保持・削除、容量と復旧 |

### 最優先の技術改善は初回MAPのデータ量の計測

入口の保守的な未圧縮予算は788,430 bytesで、設定上限1,000,000 bytes以内だった。一方、公開されたgaia-signals.jsonは取得・展開後19,591,469 bytes、約19.6 MBだった。両者は対象が異なる。入口が軽量でも、MAP操作可能までの時間、JSON解析、メモリ利用が十分とは限らない。[E1、E2、E5]

これは通信回線上の圧縮後転送量や、遅いという実測結果ではない。次にキャッシュなしの対象スマートフォンで、MAP開始から操作可能までの時間・実転送量・最大メモリを測る。問題が確認された場合、権利整理に合わせて展示別・年代別に分割し、必要な部分だけ取得する。変更後は値・欠測・凡例・描画の同値性を回帰検査する。

### 責務の分割は既存の境界から進める

app.jsは非空行で約1.1万行あり、変更影響を把握する負担が残る。ただし行数だけを品質指標にしない。データ契約、展示カタログ、モードの開始・終了・中断処理を段階的に分離し、既存のsrc/sharedとsrc/explorationを育てる。外部API統合や新しい保存基盤は、制限・費用・障害の実測に基づいて選ぶ。[E5、E7、W5]

# 06 セキュリティは利用場面ごとに設計する

### 既存の配慮は維持する

実装には、Secure・HttpOnlyのセッションCookie、CSRF用トークン、OIDCのstate・nonce・PKCE、入力サイズの上限、情報を絞ったエラーログがある。公開説明ではGoogleの氏名やメールを取得せず、主にsubを利用する方針を示している。これらは肯定材料だが、侵入試験や認証の実環境検証を今回完了したという意味ではない。[E5、E8]

### 共有端末と外部AI送信を重点的に扱う

| 論点 | 現状の確認 | 提案 |
| --- | --- | --- |
| BYOKのAPIキー | タブ内保存が標準。任意でlocalStorageに継続保存。GAIA側では中継・保管しないとの説明 | 教育・展示の共用端末ではAI機能を初期無効にする。継続保存を避け、終了時の削除を確認 |
| 任意のAI送信先 | 利用者指定先へキーと選択データを直接送信する設計 | 実証では送信先を限定し、対象データの確認・取消を必須にする。費用負担者と保存条件を明示 |
| 公開POI | 利用者が選ぶ座標が公開される。実位置と同じ場所を選ぶ危険を文書化 | 学校等では公共の代表地点を使い、児童生徒や設置場所が推測されない運用にする |
| 静的ページの防御 | ルート応答にCSP・X-Frame-Optionsヘッダーはなし。APIにはDENY等がある | CSPのReport-Only導入と埋め込み可否を検討し、地図・音・外部接続を回帰確認 |

ブラウザ内保存は暗号化された保管庫ではない。画面に追加するスクリプトやXSSの影響を受け得るため、「サーバーへ送らない」ことだけでキーの安全性を説明しない。CSPヘッダーの不在は防御改善の論点であり、今回脆弱性を実証したという主張ではない。[E1、E8]

### 外部提供前の検査範囲

認証、所有者以外のデバイス操作、トークン失効、削除、入力制限、公開プロフィール、任意送信先を対象に、OWASP ASVSの該当要件を版付きで割り当てる。テスト用環境・アカウントで実施し、本番への侵入的な試験は別途合意する。AIの説明は観測値から得た参考情報として扱い、公式な予報や政策判断の代替にしない。[W6]

# 07 品質保証を実際の運用に結び付ける

### 検査の基盤はあるが全件合格ではない

GitHub Actionsには、静的・データ検査、Chromeによる体験検査、センサー基盤の型・Pages検査が定義されている。今回も主要な静的検査は合格した。一方、単独実行した統計ラボの旧テストは、標本数237に対して31を期待し、失敗した。現在のnpm run checkの合格を、すべての関連検査が正常という意味で使わない。[E2、E3、E7]

README等の本編372・追加133という記述は、現行検査の380・164と一致しない。MAP番号も旧区分が残る。これは画面の不具合とは別だが、審査・引継ぎ・運用で誤った確認を生む。展示番号と件数を正本のカタログから生成し、旧テストを仕様に照合して修正することを提案する。[E2、E3]

### センサーの容量計画は実績とモデルを分ける

既存運用記録は、D1の全履歴走査を集計表へ置き換え、少量データ時の公開地図1更新を約22 rows readと報告している。これは2026年9月4日の記録であり、現在の負荷や規模拡大時の保証値ではない。[E7]

同記録のモデル「1日読込行数 ≒ 常時表示タブ数 × 1,440 ×（4 × 公開Device数 + 2）」を使うと、50 Device・20タブの常時表示は約582万行/日となる。現行D1 Freeの500万行/日を上回るが、これは計画用の計算であって負荷試験結果ではない。実利用時間、キャッシュ、所有者API等で実績は変わる。[E7、W7]

### 運用で記録する最小セット

- 外部APIごとの成功率、取得時刻、有効期限、保存値への退避率。
- D1の読込・書込量、API応答時間、エラー、利用量予測と費用。
- 公開したコミット、データ版、検査証跡、戻す版、復旧手順。
- 会場の事前点検と終了処理、問い合わせ、担当者不在時の引継ぎ。

公開URLのhealth応答が200であることは、D1復旧や外部データの鮮度を保証しない。小規模実証の前に、保存値への切替、表示の説明、復旧後の再取得をテスト用環境で確認する。商用提供では約束する稼働時間帯と障害対応時間を先に定義する。

# 08 90日間の実行計画

### 権利確認と実証準備を段階的に進める

以下は提案であり、実行・公開の承認を得た計画ではない。責任者は役割として記載したもので、実在の担当者を確保済みとはしていない。許諾回答待ちの間は、許諾不要または条件履行済みの代替展示で準備を進める。

### 工数と予算の考え方

概算の計画枠は合計30から50人日とする。内訳は、データ・権利整理6から10人日、品質・性能・セキュリティ改善12から20人日、体験設計・実証・事業評価12から20人日。これは見積契約や実測工数ではなく、機能追加を抑制した初期の配分案である。初期調査後に見直す。

予算は「役割別人日 × 合意単価 + 許諾・API費 + 実機・会場費 + 予備費」で算定する。許諾取得の待ち時間や外部審査費は別途見込む。新しい常勤組織を前提にせず、主担当に、権利確認と教育評価の専門支援を必要な期間だけ加える。

### この期間に優先しないこと

31本目以降の展示追加、全面的なSPAフレームワーク移行、独自LLM基盤、大規模な会員・決済基盤、行政向けの精度保証機能は対象外とする。必要性が実証された場合に、別の投資判断として扱う。

# 09 成果指標と次の投資判断

### 利用時間よりも理解と再利用を測る

下表の数値は初回実証の暫定目標であり、現状実績でも業界標準でもない。30名程度の小規模実証は、操作上の問題を発見する用途には使えるが、教育効果の一般化や統計的な因果推定には不十分である。利用者属性、参加条件、失敗・中断を含む分母を記録する。

| 指標 | 測り方と分母 | 初期の判断目安 |
| --- | --- | --- |
| 基本課題の完了 | 開始者のうち、支援なしで指定展示の比較と出典確認まで完了した人数 | 80%以上。未達なら導線・課題を修正 |
| データの読み分け | 終了時に元データ・加工値・仮定を具体例で説明できた人数 / 回答者 | 80%以上。誤読の種類も記録 |
| 理解の変化 | 同じ参加者の事前・事後の課題回答を比較 | 改善傾向を確認。対照群なしで因果効果を断定しない |
| 現場の再利用意思 | 実証した2現場の担当者に、準備負荷と次回利用条件を確認 | 両現場で再利用条件が具体化すること |
| 運用可能性 | 合意した端末と開催時間で、利用可能・退避・停止を記録 | 重大な進行停止なし。事前確認は30分以内を目安 |
| 採算の成立可能性 | 見積対象価格から直接運用・支援費を引いた案件貢献利益 | 正となる仮説を確認し、開発費回収も別に試算 |

### 90日後の判断

継続投資は、公開・商用条件が解決し、課題完了と理解の目安を満たし、再利用の具体的な候補があり、運用原価に見合う支払意思がある場合に行う。最初から定期課金を選ばず、現場の利用頻度に応じて単発開催・年間利用・支援契約を比較する。

理解の目安を満たすが支払意思が弱い場合は、教育作品としての公開、助成・協賛、展示受託等の目的を再検討する。関心は高いが理解が弱い場合は、追加演出より課題と説明を修正する。権利問題や運用上の重大な未解決事項が残る場合は、影響範囲の拡張を行わない。

### オーナーに求める決定

①公開データの是正方針、②最初の実証先と利用者、③30から50人日の計画枠、④実証を評価する責任者を決める。本レポートの提言を実装・公開する行為は今回実施していない。
